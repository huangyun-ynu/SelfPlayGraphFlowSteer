# SWE 候选补丁保护与强制收尾前补测

本次修复针对两个工程问题：失败修订覆盖最新结果后旧补丁失去恢复入口，以及已有补丁、仍有剩余额度时，运行时提前进入只能输出文字的收尾阶段。保留当前共享 token/Action 余额机制，不增加预算，不重新引入固定分额或预留。

## 候选补丁

- `SWEWorkspaceLifecycle` 将实际导出的补丁登记到当前任务的独立恢复目录。最新执行结果继续反映失败或空补丁；目录不受后续失败修订、删除节点或新建替代节点影响。
- Worker 初始状态和 Director 控制快照均展示恢复引用及原节点、工作区版本。Worker 可显式使用 `swe_apply_artifact` 恢复；恢复和测试照常计入共享工具额度。
- 引用不等于当前有效产物。恢复从基准提交上的新工作区开始，校验补丁内容；仍须满足当前图的依赖、新鲜度及修改后测试条件。历史测试不能冒充恢复后的测试，不自动提交或把旧结果升级为当前结果。
- 目录绑定单次任务，重新绑定时清空。模型请求在编辑后异常退出时，工作区收尾仍尝试导出候选。
- 失败归因只有在补丁确实失去恢复入口时才报告候选恢复失败；历史轨迹缺少目录信息时保留原有严格判断。

## 收尾前真实补测

当 task_result Worker 将要强制收尾，已有工作区修改、最新修改后尚无实际测试，且剩余 token 和 Action 额度允许时，运行时最多发起两次只允许 `swe_test` 的紧凑模型请求。它们仍走原有 token 入场检查、工具计费和真实测试执行路径。首次请求错误或没有动作时，可在剩余额度内纠正一次。

实际测试执行后再生成最终报告。没有剩余额度、测试未启动、目标错误或只有文字时，不制造测试证据；测试运行失败也不伪装为通过。公开功能测试与语法检查维持既有区分。

真实轨迹验证发现补测提示曾把普通 `.py` 源码列成测试路径，可能浪费最后一次 Action。现已排除这种误标，`django/test/` 框架源码也不视作公开测试目录；没有可据实选择的测试目标时提示使用配置好的公开冒烟测试。
