# WebShop 记忆裁剪与状态矛盾：修复设计

范围：基于合并版加 W09 身份修复的冻结源码和现有模型输入分析。本文是方案，未修改运行源码或重新评测。

## 根因和两种不同的遗忘

当前调用顺序：运行记录更新 product_inspections → 从该记录标注搜索结果 → _webshop_progress_prompt 生成最多6000字符的提示记忆 → _webshop_context_for_prompt 再用这个被裁剪的列表计算动作辅助字段。

第一种遗忘是提示展示裁剪：底层仍知道商品访问过，但 prompt.product_inspections 被删空，辅助函数按不存在返回 false。这就是已经复现的81次商品、123次详情矛盾。

第二种遗忘是底层详细缓存容量：product_inspections 本身只保留最近6个商品，sections_viewed 最多3项，而 section_evidence 最多保留最近2段、每段1400字符。即使绕开6000字符裁剪，也不能把不在这6个记录里的商品断言为从未访问。这两类问题应分别验证，不用同一个“缺失即false”规则处理。

现有测试直接把完整 product_inspections 交给辅助函数，没有覆盖实际“先压缩、后辅助判断”的组合路径，因此身份专项测试可以通过而真实请求仍出错。

## 第一轮：恢复事实一致性，保持实验范围清楚

保持现有模型、推理强度、提示策略、总预算和详细证据缓存容量。首先改 _webshop_action_decision_support 的数据依赖：

- 对 open_product，从当前合法动作中解析ASIN，并使用运行时已生成的 inspection_status/visit_count。已知 inspected 的事实不能被压缩列表中的缺失推翻。
- 对 view_section，使用裁剪前生成的当前商品 sections_viewed；可直接利用现有 decision_checkpoint.public_sections_observed，但必须校验 checkpoint.current_product.asin、state.product.asin 和动作中的ASIN一致。
- _webshop_context_for_prompt 只做展示，不再从展示列表的缺失推导否定事实。若需要通用接口，在裁剪前建立一个小型不可变 facts snapshot，搜索标记和动作辅助均消费同一份快照，压缩器不能回写它。
- 来源缺失、记录被淘汰或旧轨迹没有足够字段时，状态为 unknown；不把缺失强制转换成布尔 false。若采用 null/省略字段，必须检查全部调用者，避免 bool(None) 又把未知变回否定。若保留枚举，则显式使用 seen/unseen/unknown。

对已发现矛盾的覆盖校验：原合并版142条详情矛盾、最新版本204条商品/详情矛盾，均能在同一输入中找到与动作和当前商品身份一致的正确事实。这个修复不需要额外读商品数据库或查询隐藏目标；覆盖检查结果见 existing-fact-coverage.json。该检查不是修复后推理准确率的证明。

## 第二轮：把访问事实、证据文本、实时会话状态分开

访问事实很短，详情文本很长；不应使用同一个淘汰策略。

|层|内容|生命周期与裁剪规则|
|---|---|---|
|访问事实|稳定ASIN、是否成功观察过商品页、访问计数、成功观察过的详情名|当前rollout/session内保留；与长文本缓存分离|
|证据缓存|详情片段、选项值、标题、历史价格等|可以按容量缩短/淘汰，但必须记录是否保留完整证据|
|实时状态|当前页、当前合法target_id、最新selected_options、当前预算与state_version|只认当前环境响应，不能由历史覆盖|

当前动作总上限为16，成功打开的不同商品数量也受这个动作预算约束。保留每个已打开商品的短身份记录，和把完整页面历史塞进提示，成本不同。实现应随实际动作预算/会话生命周期管理，不能硬编码只适用于这128题的上限或商品列表。

后台事实可覆盖整次rollout，提示只展示当前页面和当前可选动作需要的状态，不需要每轮注入全部身份索引。初次执行、revision、持久化恢复都应使用同一事实结构；新任务清空，所有者变化遵循原事务继承规则，不借机共享其他会话的私有状态。

这层改动改善六商品缓存淘汰后的判断，应作为独立消融，避免与第一轮6000字符裁剪修复混在一起后无法分辨作用。

## “读过”不能等同于“重开没有价值”

当前 may_add_product_page_evidence / may_add_section_evidence 直接取已访问状态的反值，含义过强。

至少分清三个事实：是否访问过、相关证据是否仍在当前模型输入里、内容是否已知发生变化。已访问但证据不再保留的页面，重新打开可能用于恢复证据；已访问的商品也可能需要返回选择规格或购买。

因此：已访问标记只报告历史，不直接禁用动作；无法判断新增信息时，不声称一定无价值。后续可将“新证据”与“恢复证据”区分，或删除无法可靠推断的价值布尔值，只保留事实。固定详情内容哈希可帮助区分相同内容与变化，但哈希只能表示内容是否相同，不能代替原始证据，也不能证明任务条件已满足。

这一语义调整会影响探索偏好，宜和最小一致性修复分开比较。

## 压缩规则

6000字符上限可以继续保留，但压缩前后必须保持已确定的访问事实不变。优先缩短重复说明、候选长文本和旧证据片段，保留与当前合法动作有关的短状态。第一轮可保持现有裁剪顺序、只纠正事实来源，以隔离效应；第二轮再调整展示分配。

不得以“完整历史进入模型”作为默认修复，这会同时改变上下文长度和成本。也不得因为缓存中没有某商品记录就增加一条强提示告诉模型重复搜索；未知应如实表达。

## 验证与验收

1. 重放现有原始请求：商品标记和辅助标记、详情检查点和辅助标记的矛盾均为0；按请求/动作和独立题目分别计数。
2. 组合回归测试必须经过真实压缩路径，强制让 product_inspections 被裁掉，检查状态不翻转；改变压缩额度时，已有事实应保持不变。
3. 访问第7个商品后返回第1个：如已保留短事实则保持seen；如果第一轮仍无完整记录则unknown，不能因为被缓存淘汰就标为unseen。
4. 读过三个详情但仅保留两个文本；访问状态、文本保留状态分别正确。商品A读过Features不能污染商品B。
5. 新任务、持久化恢复、revision和所有者交接的状态范围正确；失败动作、请求失败和无效目标不写入成功访问记录。
6. 页面序号重排仍按ASIN关联，target_id只用于当前页面，不在历史中重新生成合法动作；同名商品不能合并。
7. 离开/重开商品导致选项重置时，只使用最新selected_options。历史访问事实不能把旧选项恢复成当前选择。
8. 所有当前合法动作保持可选。允许为购买、补查和恢复证据重开，不能把“重复打开变少”当成唯一优化目标。
9. 检查投影函数不修改底层事实，状态版本一致，并记录输入字符数和实际token开销。
10. 离线一致性通过后，再同配置跑128题，报告严格成功率、reward、成本、循环动作及未购买情况。减少字段矛盾不等于保证提高准确率，不承诺恢复所有涉及失败。

建议先完成第一轮，让事实表达正确；再根据同预算轨迹判断是否需要第二轮的持久访问索引和证据保留改进。整个设计属于通用状态管理，不是Skill、题目专用规则或增加推理强度。
