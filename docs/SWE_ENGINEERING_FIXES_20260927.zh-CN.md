# SWE 工程缺陷修复记录

日期：2026-09-27。实施位置：`SelfPlayGraphFlowSteer-output-contract-v1` 当前源码。历史 `full-v5` 冻结源码、样本和成绩保持原样。

## 1. 已测试补丁被旧输出角色标记误判

原问题：统一协议的 `task_result` 不使用 `selected_as_output`，但补丁完成后的重复只读拒绝豁免仍要求该旧标记为真，导致完整性评估提示重跑，而提交评估认为补丁已经就绪。

修复：完整性评估按当前 `result_scope=task_result` 判断；缺少新版职责字段的旧记录继续兼容旧输出标记。豁免同时要求可信、可提交、工作区确有修改、最新修改后已有测试，而且最后一个错误必须是只读请求的 `repeated_no_progress_action`。写入错误、运输错误、未测试等情况继续保留风险；原始失败轨迹和计数仍留档。

回放 `django__django-14315 / artifact_2`：保留原 `selected_as_output=False` 和全部进度证据，`terminal_tool_failure` 消失，`can_run=False`。本地集成测试确认：仅有图连接阻塞时不重跑候选，删除无关节点解除阻塞后，`finish(target)` 可直接提交原候选。

## 2. 工具用完后仍启动新 SWE 执行

原问题：显式续行先根据 missing/dirty/完整性恢复返回可执行，才检查工具余额；自动执行和双向修订也缺少统一的工具资源检查。

修复：共享整题账本下，需要 SWE 工具的新执行统一读取当前余额。显式 `run_agent` 先检查资源；运行时在缓存复用之后、真正进入执行器及创建工作区之前再次检查，覆盖初次配置、图编辑、自动 dirty 执行、显式恢复和双向修订。某个节点恰好用完最后一次工具时，后续节点和修订也会被拦下。

- 当前 Worker 已经启动后的有界文本收尾继续执行；输入相同的有效缓存仍可零工具复用。
- 被拦下的阶段记录到 `ExecutionReport.blocked_agents`，不伪造模型调用、产物或 token 消耗。
- 保留历史产物作为证据，同时保持受影响节点、双向组件及下游为 dirty；不把未完成的同步修订当成有效新结果。
- 调度时新发现的 stale 节点若先用完额度，显式目标会收到真实的阻塞反馈，不会被报告为已经执行。
- 新依赖使旧候选失效的规则继续生效；保存旧补丁不等于允许绕过当前输入绑定提交。

## 3. 共享预算错误码漏配

补齐 SWE 的 `total_action_budget_exhausted` 分类映射。仍要求独立的最终协议/预算等终止证据；不根据这一错误码单独判零，不覆盖未知工具故障、基础设施故障或尚未终止的运行。

对原始 6 个相关未知样本离线重算：5 个可依据原有证据获得类型化终止归因，`django__django-11555` 继续保持未知。未回写原始状态、分数或训练结果。
