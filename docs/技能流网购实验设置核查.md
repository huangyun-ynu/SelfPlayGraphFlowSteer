# SkillFlow 的 WebShop 设置核查

核查日期：2026-09-24。本文以项目此前引用的 SkillFlow 固定提交 [`74be52bb6bd9f0e9e68dacb72636b75649197983`](https://github.com/beita6969/SkillFlow/tree/74be52bb6bd9f0e9e68dacb72636b75649197983) 为代码依据，另核对了官方公开数据集和论文。下文区分**代码默认值**、**可选开关**与**论文报告结果**；仅凭默认配置不能证明论文每次运行的全部实际参数。

## 1. WebShop 的执行架构

当数据记录的 `task_type` 是 `webshop`，训练器调用 `_run_react_episode`：Supervisor 读取购物目标、当前页面、合法动作和本题历史，输出一个文本动作；WebShop 环境执行后返回新页面和奖励。普通搜索和点击直接交给环境，并不先委托 `M_exec` 生成动作。`M_exec` 是 SkillFlow 跨任务框架中的冻结执行器，不能与本项目的 WebShop Worker 画等号。对应源码：[训练器](https://github.com/beita6969/SkillFlow/blob/74be52bb6bd9f0e9e68dacb72636b75649197983/training/gflownet_trainer.py#L686)、[WebShop 循环](https://github.com/beita6969/SkillFlow/blob/74be52bb6bd9f0e9e68dacb72636b75649197983/training/gflownet_trainer.py#L802)。

| 项目 | 固定版本的 WebShop 专用路径 |
| --- | --- |
| 决策模型 | Supervisor；配置的基础模型默认 `Qwen/Qwen3.5-9B`，可由环境变量覆盖 |
| 每次请求 | 单条 `user` 消息，内容是完整拼接的 ReAct 提示 |
| 动作协议 | 文本 `search[关键词]`、`click[页面元素]`；另支持 `skill_invoke[技能ID]` |
| 动作生成 | `temperature=0.8`、`max_tokens=512`、`enable_thinking=False` |
| 未指定项 | ReAct 请求未显式指定 API seed、`top_p`、`top_k` |
| 每题步数 | 10；覆盖训练 YAML 中通用的 `max_episode_steps=12` |
| 请求异常重试 | 外层最多 3 次；不包含 OpenAI SDK 自身可能进行的重试 |
| 时间上限 | 客户端 HTTP timeout 为 300 秒；题目循环在每步开始前检查 600 秒墙钟时间 |
| 购买 | 环境的购买点击产生 `done/reward` 后直接终止；没有本项目的暂存、选择、最终提交过程 |

辅助函数 `react_call` 自身有 `max_tokens=256` 的默认参数，但训练器**调用时传入 512**。技能调用和无效动作也占一次循环步数；解析失败会保留当前提示继续，达到上限仍未完成则按 0 分截断。参考：[API 请求及动作解析](https://github.com/beita6969/SkillFlow/blob/74be52bb6bd9f0e9e68dacb72636b75649197983/training/batch_inference.py#L734)、[任务配置](https://github.com/beita6969/SkillFlow/blob/74be52bb6bd9f0e9e68dacb72636b75649197983/training/task_prompts.py)、[动作处理](https://github.com/beita6969/SkillFlow/blob/74be52bb6bd9f0e9e68dacb72636b75649197983/training/environment.py#L8331)。

## 2. 环境、商品和目标划分

配置优先级主要是单条数据的 `env_config`、相关环境变量、代码默认值。每条记录中的 `seed` 用来在选定目标池中选题，与环境初始化的 `env_seed` 不同。[环境适配器](https://github.com/beita6969/SkillFlow/blob/74be52bb6bd9f0e9e68dacb72636b75649197983/src/ragen_adapter.py#L320)。

| 参数 | 默认值／行为 |
| --- | --- |
| `observation_mode` | `text` |
| `WEBSHOP_HUMAN_GOALS` | `False` |
| `WEBSHOP_USE_SMALL` | `True`，默认商品和属性文件分别为 `items_shuffle_1000.json`、`items_ins_v2_1000.json` |
| 关闭 `WEBSHOP_USE_SMALL` | 改用 `items_shuffle.json`、`items_ins_v2.json` |
| `WEBSHOP_NUM_PRODUCTS` | `None`，也可在 `env_config` 指定 |
| `WEBSHOP_FILE_PATH` / `WEBSHOP_ATTR_PATH` | 覆盖上述数据文件路径 |
| `WEBSHOP_ENV_SEED` | `1000`，环境初始化种子 |
| `WEBSHOP_GOAL_SPLIT` | `skillrl_val`，取目标列表前 500 个；`val/eval/test` 等同义值行为相同 |
| `train/skillrl_train` | 目标数大于 500 时取第 500 个及以后，否则取全部 |
| `all/full` | 使用全部目标 |
| `WEBSHOP_GOAL_OFFSET` / `WEBSHOP_GOAL_COUNT` | 显式目标区间，优先于 `GOAL_SPLIT` |
| 单条记录 `seed` | 在选定目标池内取模选题；例如 500 个目标时 `seed=3154` 选池内第 154 个 |
| 单条记录 `goal_index` | 直接指定环境目标编号，优先于 `seed` |

环境 `reset` 失败时，适配器会尝试退回目标 0；严谨复现实验需要核对实际运行记录中的目标编号。[目标映射源码](https://github.com/beita6969/SkillFlow/blob/74be52bb6bd9f0e9e68dacb72636b75649197983/src/ragen_adapter.py#L384)。

## 3. 提示词、原题与交互历史

`WEBSHOP_PROMPT_STYLE` 默认 `raw`，还有 `skillrl` 和 `agentbench` 两种可选模板：

| 风格 | 给模型的主要内容及输出要求 |
| --- | --- |
| `raw`，默认 | 购物目标、当前页面、合法动作、此前的观察与动作；只输出一个 `search[...]` 或 `click[...]`，点击值从合法列表准确复制 |
| `skillrl` | 相同的任务和页面信息；额外要求以 `<think>` 和 `<action>` 标签输出 |
| `agentbench` | 任务、观察与动作列表；强调选择可执行动作和设计搜索词 |

`skillrl` 模板要求写 `<think>`，**不表示 API thinking 已开启**：这份 ReAct 代码的请求参数仍明确设为 `enable_thinking=False`。默认 `raw` 模板也没有本项目 LASER 的逐项核对清单。[三种模板](https://github.com/beita6969/SkillFlow/blob/74be52bb6bd9f0e9e68dacb72636b75649197983/training/react_prompts.py)、[模板选择](https://github.com/beita6969/SkillFlow/blob/74be52bb6bd9f0e9e68dacb72636b75649197983/training/environment.py#L7694)。

WebShop 专用路径优先从初始环境观察中解析购物任务，不符合预期格式时使用数据记录中的 `question`。原题由程序插入模板，不需要 Supervisor 自行重写。每次操作后保存**动作前观察＋动作**；下一步重新拼接本题完整历史和当前页面。该分支没有按商品数量或最近 N 步裁掉 WebShop 历史，但仍受模型上下文窗口及服务能力限制。历史记录不等于重放先前完整模型输出。[初始化与任务来源](https://github.com/beita6969/SkillFlow/blob/74be52bb6bd9f0e9e68dacb72636b75649197983/training/environment.py#L8127)、[历史组装](https://github.com/beita6969/SkillFlow/blob/74be52bb6bd9f0e9e68dacb72636b75649197983/training/environment.py#L9647)。

源码另外存在一条通用工具路径，包含更强的 WebShop 购物示例、“尽快选择合理商品”等提示。**那条路径与 `task_type=webshop` 的专用 ReAct 模板不同**，不能把它的提示直接归给上述默认 WebShop 运行。[通用工具路径](https://github.com/beita6969/SkillFlow/blob/74be52bb6bd9f0e9e68dacb72636b75649197983/training/environment.py#L987)。

## 4. 可选辅助开关与实际调用关系

| 开关／函数 | 默认与核查结果 |
| --- | --- |
| `WEBSHOP_ENV_FEEDBACK` | 默认关闭；开启后添加重复查询、返回搜索页、浏览过的商品等来自可见历史的事实反馈 |
| `WEBSHOP_VISIBLE_STATE_FEEDBACK` | 默认关闭；开启后汇总题目中的价格／属性、近期搜索、访问记录、当前页面、可见选项等 |
| `WEBSHOP_ORDER_ACTIONS` | 默认关闭；开启后重排展示给模型的动作列表 |
| `WEBSHOP_ALLOW_STRONG_GUIDANCE`、`WEBSHOP_STRONG_GUIDANCE` | 都默认关闭；相关强引导判断函数在 WebShop 主执行路径未被调用 |
| `WEBSHOP_SOFT_EXACT_WARNING` | 默认关闭；仅发现辅助函数定义，未发现主路径调用 |
| 精确选项强制 guard | 对应函数直接返回 `False` |
| `WEBSHOP_SIMPLE_RANK_FIRST` | 默认关闭，属于未接入主路径的商品排序辅助函数 |
| `WEBSHOP_SEARCH_RANK_FIRST` | 辅助排序函数内部默认真；不能据此认为主路径默认替模型挑第一个搜索结果 |
| `ALFWORLD_LOOP_GUARD` | 默认关闭；共享动作循环的判断未限定 ALFWorld，若全局打开，可能影响 WebShop 重复动作 |

这里区分了**函数存在**和**主路径调用**。仅凭代码里有推荐商品、推荐选项等函数，不能推断 WebShop 实验启用了它们。[开关及主路径](https://github.com/beita6969/SkillFlow/blob/74be52bb6bd9f0e9e68dacb72636b75649197983/training/environment.py#L7664)。

## 5. 技能机制

官方 YAML 的 `skill_mode` 为 `policy_action`。工作区非空时，WebShop 提示最多列出 4 个相关技能的 ID 和名称；Supervisor 可以用 `skill_invoke[ID]` 取得技能策略、易错点和约束，然后继续购物。技能调用占一次动作步数。默认 `genesis_count=0`，空工作区启动时不会先生成初始技能；训练过程仍可能演化出技能。恢复已有技能工作区时要以实际工作区内容为准。[技能目录](https://github.com/beita6969/SkillFlow/blob/74be52bb6bd9f0e9e68dacb72636b75649197983/training/environment.py#L932)、[调用处理](https://github.com/beita6969/SkillFlow/blob/74be52bb6bd9f0e9e68dacb72636b75649197983/training/environment.py#L8360)、[配置](https://github.com/beita6969/SkillFlow/blob/74be52bb6bd9f0e9e68dacb72636b75649197983/configs/skillflow.yaml)。

旧式直接注入策略的路径，初始最多取 2 条、后续最多取 1 条。相关默认值为 `WEBSHOP_SKILL_ENABLED=True`、`WEBSHOP_SKILL_PLACEMENT=prefix`；也支持关闭注入或使用 `skillrl_memory`。`WEBSHOP_SKILL_ON_INIT=True` 影响特定初始经验注入分支。

**关闭 `WEBSHOP_SKILL_ENABLED` 不足以保证无技能实验**：`policy_action` 的技能目录构造分支没有检查此开关。需要同时检查工作区是否为空、模型实际收到的技能目录以及轨迹里有无 `skill_invoke`。[两条技能路径的条件](https://github.com/beita6969/SkillFlow/blob/74be52bb6bd9f0e9e68dacb72636b75649197983/training/environment.py#L8181)。

## 6. 数据集、训练和评测

官方公开文件包含 **500 条 WebShop 训练记录、128 条 IID 验证记录**；记录的 `task_type` 实际为 `webshop`，`env_config` 明确包含 `observation_mode=text` 和单题 `seed`。[官方数据集说明](https://huggingface.co/datasets/beita6969/SkillFlow-Dataset)。仓库里的旧 `data/prepare_v3.py` 却把 WebShop 生成为 `interactive_agent`、`metric=exact_match`。因此**旧准备脚本的输出不能直接当作公开 JSON 的等价副本**，尤其会影响执行路径。[旧准备脚本](https://github.com/beita6969/SkillFlow/blob/74be52bb6bd9f0e9e68dacb72636b75649197983/data/prepare_v3.py#L137)。

| 跨任务训练配置 | YAML 值 |
| --- | --- |
| 算法、奖励 | `gflownet_ttb`、`outcome_only` |
| 步数、批量、并发 | `max_steps=300`、`batch_size=28`、`rollout_workers=28` |
| 每题训练轨迹数 | 4；这是训练采样设置，不是一次测试允许连续重试 4 次 |
| Supervisor LoRA | rank 64、alpha 128，目标为 q/k/v/o projection |
| 后向策略 LoRA | rank 16 |
| 学习率、梯度裁剪 | `1e-4`、`3.0` |
| KL、β、ε | `0.01`、`1.0`、`0.1` |
| TTB 归一化 | 每个动作按 token、每条轨迹按步数 |
| 初始技能生成／探索轮数 | 0／0 |
| 最大技能数 | 60 |
| 平台检测 | 窗口 10、ρ=0.05、连续 2 次 |
| 检查点、LoRA 同步 | 每 10 步／每 1 步 |
| 训练采样偏移 | `seed_offset=7` |

配置依据：[官方 YAML](https://github.com/beita6969/SkillFlow/blob/74be52bb6bd9f0e9e68dacb72636b75649197983/configs/skillflow.yaml)。

WebShop 环境返回 0～1 的**分级 reward**；严格成功要求 reward 等于 1。相应正式指标是平均 reward（通常乘 100 展示为 Average Score）和严格成功率 SR，**不是 QA 的 token F1**。训练器内部 `reward >= 0.5` 的“correct”跟踪阈值不能当作严格成功率。[环境中奖励与成功字段](https://github.com/beita6969/SkillFlow/blob/74be52bb6bd9f0e9e68dacb72636b75649197983/src/ragen_adapter.py#L433)、[内部跟踪阈值](https://github.com/beita6969/SkillFlow/blob/74be52bb6bd9f0e9e68dacb72636b75649197983/training/gflownet_trainer.py#L675)。论文表中 WebShop 报告 Average Score **94.73**、SR **93.75%**；那是完整方法的论文结果，不代表未训练、空技能库、仅套用原始提示后的表现。[论文主结果表](https://arxiv.org/html/2605.14089v1#S5)。

## 7. 轨迹保存与复现边界

可设 `REACT_TRACE_DIR` 或 `WEBSHOP_TRACE_DIR` 输出逐步日志；`REACT_TRACE_FULL_PROMPT`、`WEBSHOP_TRACE_FULL_PROMPT` 默认关闭。普通日志中的前后观察各最多 2000 字符，历史尾部仅 4 条且每条观察最多 300 字符，模型输出最多 1500 字符；即便打开 full prompt，也只记录前 20000 字符。[逐步日志实现](https://github.com/beita6969/SkillFlow/blob/74be52bb6bd9f0e9e68dacb72636b75649197983/training/environment.py#L8276)。

训练循环每 5 步抽样保存轨迹，每种任务类型抽 1 条、总数最多 4 条。YAML 有 `dump_trajectories: true`，但在该提交的训练器中未发现读取此字段来实现全量保存。因此要逐题复核，需另行核对是否启用了完整请求／响应审计。[轨迹抽样代码](https://github.com/beita6969/SkillFlow/blob/74be52bb6bd9f0e9e68dacb72636b75649197983/training/gflownet_trainer.py#L2492)。

本项目曾实现两种**局部适配**：`skillflow_history_v1` 移植完整历史，但保留本项目的 Worker、LASER、图工具和购买协议；该模式已于2026-09-27移除，实验记录保留。`skillflow_native_v1` 是独立的原生协议适配，移植原始无技能模板、文本动作和历史，但保留 Director／Worker 编排、独立会话、暂存购买和 12＋4 动作预算。它们都不是 SkillFlow 原控制器的完整复现。可对照本项目的[历史适配记录](WEBSHOP_SKILLFLOW_HISTORY_ADAPTATION.zh-CN.md)和[原生协议适配说明](WEBSHOP_SKILLFLOW_NATIVE_V1.zh-CN.md)。
