## 修改

第一轮（`after`）：

- Worker 未暂存购买时，可信进度状态改为 `no_purchase_candidate`；分析 Agent 仍可正常汇报。
- Native WebShop 的 Director 控制快照增加 `environment_task_status`：输出 Agent、当前真实候选、是否已提交，以及每个 Agent 可用的初始/修订/累计动作额度。候选读取实时 lifecycle，额度读取共享账本，不从旧 Artifact 或模型自述推断。
- 提示明确图结构允许 FINISH 不等于购物完成；新 Agent 不增加全图动作预算，修订会撤销该 Agent 的旧候选；购物职责不能用清单汇报代替暂存购买。
- 提醒 Worker 暂存购买也消耗动作，当前阶段结束后不能自动使用修订额度。

第二轮（`after2`）：在第一轮已完成轨迹中发现未选择所需口味、仅核对标题和价格即购买的情况，补充公开环境语义：标题含有规格名称不等于已选择该规格；标题未提供所需属性证据时应查看公开详情。没有按任务 ID 或隐藏目标添加规则。

两轮均保留通用 Agent、自主图结构、独立会话、合法图边通信、完整私有历史、12+4=16 全图动作预算，以及 FINISH 才提交的机制。原 SkillFlow 两份原始页面模板保持不变；变化位于适配层指令。没有添加 skill、强制购买、自动选择商品或按隐藏奖励挑候选。无购买结束仍合法并计零分。

Director token 使用每次调用真实 prompt/completion token IDs 长度之和，包含关系选择；Worker 使用记录中的 `token_cost`。此口径沿用本轮比较，不与旧 128 题的请求 usage 统计直接混合。Artifact 中未发现 backend_request_failure 事件；运行器零失败也不等于穷尽所有潜在 API 异常。

最终相关回归 **181 passed**（Native、Director/Canvas、三种上下文模式、history、请求预算），Ruff 检查与格式检查通过。新增/扩展验证覆盖：分析报告不冒充购买完成、共享额度不因新 Agent 重置、实时候选撤销不受旧 Artifact 干扰、提交后的最终状态，以及非 WebShop 的控制快照不受影响。配置单测使用假的凭据解析器，不再依赖旧机器的私有密钥文件。
