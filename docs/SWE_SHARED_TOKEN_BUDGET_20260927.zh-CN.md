# SWE Worker 共享 token 余额修复与回归

2026-09-27 按用户确认实施：取消 SWE Worker 的固定分额和收尾 token 预扣，改为整题共享余额。策略标识为 `swe_shared_request_credit_v1`。

## 执行规则

- 每题 Worker token 总上限继续使用 `max_total_tokens`；当前 SWE 配置为 **350,000**。不同题目各自记账。
- Canvas 不再用“剩余额度 ÷ 预计执行次数”分配 SWE 额度，也不再用历史成本估算和收尾预留拒绝建图、改图。实际请求发送前的预算检查仍然生效。
- 当前图执行器按顺序执行 Worker。每次真正执行，包括双向修订、补发现的陈旧节点和显式 `run_agent`，都取得当时整题剩余余额；缓存命中不扣 token。
- 同一 Worker 内每次请求使用“执行开始余额 − 本次执行已经产生的输入和输出 token”。收尾请求也使用此余额，不预先扣留一份收尾费用。
- 网关继续在每次实际请求前检查序列化输入的保守上界与输出额度；必要时缩小输出上限，输入和最低输出仍放不下时不发请求。长度修复和路由切换也接受检查。
- 请求结束后扣实际已知 usage；删除重建节点、换路由或重试不重置整题累计消耗。最终产物中的 token 数覆盖该次执行的全部已知消耗。

`remaining_token_admission_enabled` 和 `finalization_token_reserve` 不再使 SWE 恢复旧的预测分额或预留；它们在其他数据集中的行为保留。SWE 的 32 次共享工具额度、无进展保护继续生效。Director thinking、增量上下文和 masked GRPO 训练语义未改动。

## 同时修复的记账遗漏

真实网关路径的离线回归发现：一个路由先完成了有 usage 的响应，随后长度修复失败并切换路由，最终返回的响应可能只包含成功路由的 usage。现在 SWE 取请求账户累计已知 usage，避免遗漏失败路由此前已经完成的生成，同时避免重复扣减。

如果整个后端请求最终失败，Worker 失败产物仍保留本次执行此前工具交互、长度修复及收尾过程中已经产生的已知 usage，并计入 Canvas 的整题余额。
