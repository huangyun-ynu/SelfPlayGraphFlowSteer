# SWE 未提交失败的工程归因修复

实施日期：2026-09-27。代码位置：`SelfPlayGraphFlowSteer-output-contract-v1`。

## 修复结果

统一提交协议下，未提交的 SWE 题目先检查运行时历史，再判断能否标为 `policy_failure`。出现已知工程干扰或请求预算证据不足时，结果保持 `unsubmitted_unknown`，`score_known=false`、`task_reward=null`，排除出有分数的训练样本。停止原因仍按原记录保留，例如 Director 上下文耗尽；停止原因不再覆盖已经发现的工程干扰。

新增的 `task.metadata.swe_failure_attribution` 会随评测轨迹及训练侧诊断元数据保存，包含版本化来源、具体原因、事件/产物 ID、相关余额或补丁哈希及恢复状态。数据来自运行时账本、工具执行观察和导出的补丁引用，模型文字、自述原因和 thinking 不参与判断。

| 原因码 | 判定条件 |
| --- | --- |
| `swe_request_credit_allocation_blocked` | 请求因单次信用额度拒绝，但当时整题共享余额足以支付输入上界加最小允许输出。覆盖普通请求与收尾请求。 |
| `swe_candidate_recovery_failed` | 运行时导出的非空候选被同节点的失败执行替换，失败结果没有补丁引用，也没有成功修改工作区的证据；当前健康产物中未恢复相同补丁。 |
| `swe_request_budget_evidence_incomplete` | 有运行时请求额度拒绝记录，但缺少必要报价字段，无法证明是模型耗尽真实余额。 |

预算比较使用每次执行发生时的实际累计消耗，计入同一执行波中先运行的 Worker、被删除节点的历史费用和失败请求前的已消费 token。缓存复用不重复扣算。最小输出与当前网关一致，为 `min(128, configured_output_bound)`；历史收尾诊断缺少分阶段费用时，保守使用该次执行的完整费用。

候选检查覆盖跨 Canvas 步骤，以及同一步骤内“初次生成补丁→双向修订失败”。显式续行保留原候选、主动删除后重建节点、正常替换结果和成功编辑后主动撤回修改，不据此认定候选恢复失败。健康产物重新提供同哈希的可信补丁后，对应事件标为已恢复。

## 评分边界

- 整题余额确实不足时，额度拒绝本身不会被误判为错误分额；是否属于策略失败继续要求独立的终止证据。
- 没有工程干扰的协议失败/终止失败仍可按原规则得到 `policy_failure`。
- 即使开启 `uncertain_failure_zero` 兜底，已识别的工程干扰也不会被再次改写为已知零分；训练侧继续排除这类未知结果。
- 已有合法提交回执及验证结果的成功或失败分数继续保留。历史失败诊断不能覆盖正式提交成绩。
- 这里的 `runtime_or_mixed` 表示存在工程干扰，不能独立断定纯模型责任，也不表示修复工程问题后模型必然成功。
